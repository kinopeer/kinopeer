# Release checklist

What to check before every release, and what to settle before Kinoseed (the repo, the Docker image or both) goes public. Releasing itself is in [DEVELOPMENT.md](DEVELOPMENT.md) → Releasing.

## Before every release

Go through these for the release PR (the one with the version and the changelog section) and note what was found in its description.

- **The test-gap pile.** List the issues closed since the last release with a `test-gap:*` label, one label at a time: `gh issue list --state closed --label test-gap:uncovered --search "closed:>YYYY-MM-DD"`, and the same for `wrong-layer`, `implementation`, `fake-drift`, `environment` and `silent-test`. Three of one class are a problem of the system, not three accidents; the action per class is in [TESTING.md](TESTING.md) → When we find a bug (three `fake-drift` → compare the fakes with the live services by hand, three `wrong-layer` → rewrite the layer rule, and so on).
- **The suite itself.** New duplicates between layers (a statement checked twice without a comment saying what the second layer sees); the coverage totals against the threshold (`npm run test:coverage`; raise the threshold when the totals have grown, [TESTING.md](TESTING.md) → Coverage); `npm test` still under 15 seconds on the owner's Mac and the `visual` job still around a minute in CI, or find what got slow; no `flaky` in the recent `visual` job logs.
- **By hand, what no layer sees** ([TESTING.md](TESTING.md) → Known blind spots), on `main` as it will be released: on the owner's phone (Safari on iOS, against `dev-lan`) open Downloads, a title and its releases, drag a sheet closed by its title and swipe behind an open sheet (the page doesn't move), and check that the installed PWA still opens; after the Umbrel package updates, go through onboarding, a search and adding a release through Umbrel's app_proxy and HTTPS; add a release over plain `http://` on the LAN, where the info hash from the SHA-1 fallback must match qBittorrent's.

## Before the public release

Things to settle before Kinoseed goes public. Add an item whenever something comes up that can wait until then; tick it off in the PR that settles it.

- [ ] **README search screenshot.** `docs/screenshots/search.png` still shows the old trending and popular rows (Search shows new on digital, new episodes and the best of the year since 0.6). Retake it with `npm run screenshots:readme`, which needs a TMDB key, and update its alt text in `README.md`.
- [ ] **TMDB key.** For now everyone enters their own key. Decide whether Kinoseed ships a default one. A key in the code, the image or the git history is public: anyone can pull it out, misuse is tied to the owner's TMDB account, and a revoked key breaks every install at once. If there is a default, register a separate key for Kinoseed (not a personal one) and keep `TMDB_API_KEY` and the Settings sheet as overrides.
- [ ] **TMDB attribution.** TMDB's API terms ask apps to show the TMDB logo and the notice "This product uses the TMDB API but is not endorsed or certified by TMDB." The README has it; the app doesn't yet (Settings → About would fit).
- [ ] **License.** The repo has no `LICENSE` file yet. Candidates: GPL-3.0 (like Sonarr and Radarr, forks stay open) or MIT.
- [x] **Secrets in history.** Checked 2026-10-28 with gitleaks v8.30.1 (`gitleaks git --log-opts="--all"`) over every branch, tag and pull request head on GitHub: 229 commits with text changes (the other 4 change only screenshots), no keys or passwords. Its 9 findings are one false positive, the path `src/api/qbittorrent/` in `CLAUDE.md` read as a generic API key. A search of the same history for local addresses found only placeholders (`192.168.1.10` in code comments, `umbrel.local`, `kinoseed.local`) and test values, and the README screenshots in every version show fixture data. Check again just before the repository goes public, if commits have landed since.
- [x] **Default qBittorrent login.** Settled 2026-10-23: the Umbrel package keeps `admin`/`adminadmin`. It is Umbrel's default, it is tried once, and Kinoseed asks for the login after that.
- [ ] **Official Umbrel App Store.** The image (`ghcr.io/mrshakhov/kinoseed`) and the [Homelab Community App Store](https://github.com/MrShakhov/umbrel-homelab-store) are already public. Submit to getumbrel/umbrel-apps: manifest, icon, gallery screenshots, release notes, multi-arch image pinned by digest.
- [ ] **Links in the Umbrel manifest.** `website` and `support` in the store's `homelab-kinoseed/umbrel-app.yml` point at the public store repository and `repo` is empty while this repository is private. When the code goes public, point them and `repo` back at this repository.
- [x] **HTTPS.** Settled 2026-10-25: umbrelOS 2.0 serves Kinoseed over HTTPS with Umbrel's own certificate, and Kinoseed sets up nothing and works over plain HTTP. HTTPS set up by Kinoseed and push notifications are in [ROADMAP.md](ROADMAP.md) → Not planned.
- [ ] **Installing outside Umbrel.** Not supported yet; planned for 0.9 ([ROADMAP.md](ROADMAP.md)). When it comes: Kinoseed needs its own login (for example `KINOSEED_PASSWORD`), because without Umbrel's login anyone on the network can control qBittorrent and delete files; and onboarding must work on a clean install with qBittorrent and Prowlarr set only through the environment.
- [ ] **Feature requests.** Ideas go to [GitHub Discussions → Ideas](https://github.com/MrShakhov/kinoseed/discussions/categories/ideas), where people upvote them; issues are for bugs and for work we've decided to do, with a plan. Discussions are on since 2026-10-24, with an Ideas form (`.github/DISCUSSION_TEMPLATE/ideas.yml`) and links to Ideas and Q&A when opening an issue (`.github/ISSUE_TEMPLATE/config.yml`). Bugs have a form (`.github/ISSUE_TEMPLATE/bug_report.yml`) that asks for the steps and the environment [TESTING.md](TESTING.md) → When we find a bug needs, and the README links Ideas, bug reports and Q&A. Still to do when the repository goes public: a link to Ideas from Settings → About.
- [ ] **Required checks on `main`.** While the repository is private on GitHub's free plan, branch protection and rulesets aren't available, so CI isn't required to merge and "Allow auto-merge" stays off: PRs are merged by hand once every check passes. `gh pr merge --auto` doesn't wait in this setup: with nothing blocking the merge it merges right away, even while checks are running. When the repository goes public, protect `main` with the `check`, `docker` and `visual` checks required, then turn on auto-merge.
- [ ] **Features before 1.0.** Versions 0.2 to 0.4 from [ROADMAP.md](ROADMAP.md) are out; 0.5 (HTTPS and notifications) was dropped on 2026-10-25. Versions 0.6 to 0.9, planned on 2026-10-28, are still to come.
- [ ] **Prowlarr key from another app's data.** The Umbrel package mounts Prowlarr's config folder read-only to read its API key (the folder, not the file: a file bind mount would keep pointing at the old file after Prowlarr rewrites it). Umbrel's own Prowlarr package links apps the same way (its media-app-configurator mounts other apps' data), but the official App Store review may still question it; the fallback is a Prowlarr key field in Settings, kept on the server like the TMDB key, planned for 0.9.
