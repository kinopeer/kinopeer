# Release checklist

What to check before every release. What a version waits for is in its [milestone](https://github.com/kinopeer/kinopeer/milestones); releasing itself is in [DEVELOPMENT.md](DEVELOPMENT.md) → Releasing.

## Before every release

Go through these for the release PR (the one with the version and the changelog section) and note what was found in its description.

- **The suite itself.** New duplicates between layers (a statement checked twice without a comment saying what the second layer sees); the coverage totals against the threshold (`npm run test:coverage`; raise the threshold when the totals have grown, [TESTING.md](TESTING.md) → Coverage); `npm test` still under 20 seconds on the owner's Mac (where that time goes: [TESTING.md](TESTING.md) → Layers) and the `visual` job still around two minutes in CI, or find what got slow; no `flaky` in the recent `visual` job logs.
- **BuildKit's image.** `release.yml`, `edge.yml` and `ci.yml` pin `moby/buildkit` by digest in `setup-buildx-action`'s `driver-opts`, where Dependabot doesn't look. Take the newest release that isn't an rc from <https://github.com/moby/buildkit/releases>, with its date; when it isn't the pinned version and came out a week ago or more, check that `docker buildx imagetools inspect moby/buildkit:vX.Y.Z` names the same `Digest` as `docker buildx imagetools inspect moby/buildkit:buildx-stable-1` (the image Docker's actions use by default), then put that version and digest into all three in a PR of its own before the release PR, so its `docker` check and the next Edge run try it first. When the two digests differ, Docker hasn't moved `buildx-stable-1` to that release yet: leave the pin as it is until they agree.
- **The release workflow's actions.** `release.yml`'s `docker/*` actions run only at a tag, so a version Dependabot moved since the last release first runs there: watch the tag's run, and fix it before the store PR if it fails.
- **By hand, what no layer sees** ([TESTING.md](TESTING.md) → Known blind spots), on `main` as it will be released:
  - On the owner's phone, in Safari on iOS, against Kinopeer Edge built from `main` as the release PR starts from it, which changes no code (the production image behind Umbrel's proxy, since `dev-lan` has no manifest): open Downloads, a title and its releases; drag a sheet closed by its title and swipe behind an open sheet (the page doesn't move); tap a field in Speed limits and in Move files with Downloads scrolled down by a swipe, which collapses Safari's toolbar (the sheet rises above the keyboard, Save visible, the filters and the dimmed backdrop stay); add a release, pause and resume a torrent and change its category, since every call to qBittorrent carries the `X-Kinopeer` header through Umbrel's app_proxy, which no layer runs; check that Share → Add to Home Screen over HTTPS previews Kinopeer's icon rather than a generic tile (#304) and that the installed PWA still opens, that after Umbrel updates Kinopeer the app resumed from the background (not closed from the app switcher) reloads into the new version with the "updated" toast (the page being replaced must already have the update check, which came after 0.6.1: on the first update from an older build, close the app once and check on the next one), and, in it, that the first tap on the field in Move files with Downloads scrolled down doesn't make the page or the sheet jump.
  - Throughout, with Safari's Web Inspector open on Kinopeer Edge (the phone through the Mac's Develop menu): no "Content Security Policy" error in the console (Safari's own "Refused to apply a stylesheet", one per `<select>` on a page, is expected: SPEC's decision log), and the app opening from Umbrel's home screen. A desktop Chromium over plain `http://` also says it ignored the `Cross-Origin-Opener-Policy` header, which applies only over HTTPS: expected too.
  - Umbrel's sign-in lapsing under the installed app (#303): in Web Inspector on Kinopeer Edge opened from the Home Screen, delete the `__Host-UMBREL_APP_SESSION_HTTPS` cookie (Storage → Cookies) on a screen other than Downloads and reload; Umbrel's sign-in opens over the app (with its password if Umbrel's own session is gone too), and the app comes back to that screen, working, with the cookie set for a week.
  - After the Umbrel package updates: go through onboarding, a search and adding a release through Umbrel's app_proxy and HTTPS; add a release over plain `http://` on the LAN, where the info hash from the SHA-1 fallback must match qBittorrent's.
