# Release checklist

What to check before every release, and what to settle before Kinopeer (the repo, the Docker image or both) goes public. Releasing itself is in [DEVELOPMENT.md](DEVELOPMENT.md) → Releasing.

## Before every release

Go through these for the release PR (the one with the version and the changelog section) and note what was found in its description.

- **The test-gap pile.** List the issues closed since the last release with a `test-gap:*` label, one label at a time: `gh issue list --state closed --label test-gap:uncovered --search "closed:>YYYY-MM-DD"`, and the same for `wrong-layer`, `implementation`, `fake-drift`, `environment`, `silent-test` and `flaky`. Three of one class are a problem of the system, not three accidents; the action per class is in [TESTING.md](TESTING.md) → When we find a bug (three `fake-drift` → compare the fakes with the live services by hand, three `wrong-layer` → rewrite the layer rule, and so on).
- **The suite itself.** New duplicates between layers (a statement checked twice without a comment saying what the second layer sees); the coverage totals against the threshold (`npm run test:coverage`; raise the threshold when the totals have grown, [TESTING.md](TESTING.md) → Coverage); `npm test` still under 20 seconds on the owner's Mac (where that time goes: [TESTING.md](TESTING.md) → Layers) and the `visual` job still around two minutes in CI, or find what got slow; no `flaky` in the recent `visual` job logs.
- **The release workflow's actions.** `release.yml`'s `docker/*` actions run only at a tag, so a version Dependabot moved since the last release first runs there: watch the tag's run, and fix it before the store PR if it fails.
- **By hand, what no layer sees** ([TESTING.md](TESTING.md) → Known blind spots), on `main` as it will be released: on the owner's phone (Safari on iOS, against Kinopeer Edge built from `main` as the release PR starts from it, which changes no code, the production image behind Umbrel's proxy, since `dev-lan` has no manifest) open Downloads, a title and its releases, drag a sheet closed by its title and swipe behind an open sheet (the page doesn't move), tap a field in Speed limits and in Move files with Downloads scrolled down by a swipe, which collapses Safari's toolbar (the sheet rises above the keyboard, Save visible, the filters and the dimmed backdrop stay), and check that the installed PWA still opens, that after Umbrel updates Kinopeer the app resumed from the background (not closed from the app switcher) reloads into the new version with the "updated" toast (the page being replaced must already have the update check, which came after 0.6.1: on the first update from an older build, close the app once and check on the next one), and, in it, that the first tap on the field in Move files with Downloads scrolled down doesn't make the page or the sheet jump; after the Umbrel package updates, go through onboarding, a search and adding a release through Umbrel's app_proxy and HTTPS; add a release over plain `http://` on the LAN, where the info hash from the SHA-1 fallback must match qBittorrent's.

## Before the public release

Things to settle before Kinopeer goes public. Add an item whenever something comes up that can wait until then; tick it off in the PR that settles it.

- [x] **README search screenshot.** `docs/screenshots/search.png` showed the old trending and popular rows (Search shows new on digital, new episodes and the best of the year since 0.6). Done 2026-11-07: retaken with `npm run screenshots:readme` along with the others when the fixtures lost their tracker names, alt text updated in `README.md`. Retaken in English on 2026-11-07, with the add sheet's files and a torrent's page added, when the README was rewritten for the public repository.
- [ ] **TMDB key.** Decided on 2026-11-04 (SPEC's decision log): Kinopeer's key behind its proxy on Cloudflare Workers, with a key entered in Settings or `TMDB_API_KEY` as overrides; it ships in 0.7. Before the public release: TMDB confirms in writing that the proxy fits its terms (they make the license personal and non-transferable). The README says where TMDB calls go since 0.7. Consider registering that key under a TMDB account of Kinopeer's own rather than the owner's personal one, so misuse isn't tied to a personal account. Decide how the proxy outgrows Cloudflare's Free plan: its 100,000 requests a day are the account's, cache hits included, and over them the workers refuse every call until midnight UTC, so one script looping over a cached URL, or plain growth, stops TMDB for every install without a key of its own. The options are Workers Paid ($5 a month for 10 million requests) or a WAF rate limit on `kinopeer.com`, the workers' domain since the rename, in front of them (beside the custom rule that already lets only the proxy's paths through, `DEVELOPMENT.md` → The TMDB proxy); check the day's counts in Cloudflare's dashboard first. Decide the per-IP limit with it: the worker's own is soft (`DEVELOPMENT.md` → The TMDB proxy), so a strict one is a WAF rule on `kinopeer.com` or a counter in a Durable Object.
- [x] **TMDB attribution.** TMDB's API terms ask apps to show the TMDB logo and the notice "This product uses the TMDB API but is not endorsed or certified by TMDB." Done 2026-10-28: the README has it, and so does Settings → About, with TMDB's stacked logo.
- [x] **Kinoseed's leftovers.** Renamed to Kinopeer on 2026-11-05 (SPEC's decision log). Done 2026-11-06: Kinoseed's TMDB workers are deleted, `homelab-edge-kinoseed` left the edge store, and with 0.7.1 `homelab-kinopeer` replaced `homelab-kinoseed` in the Homelab store.
- [x] **License.** Settled 2026-11-07 (SPEC's decision log): GPL-3.0-or-later, in `LICENSE`, `package.json` and the README.
- [x] **Secrets in history.** Checked 2026-10-28 with gitleaks v8.30.1 (`gitleaks git --log-opts="--all"`) over every branch, tag and pull request head on GitHub: 229 commits with text changes (the other 4 change only screenshots), no keys or passwords. Its 9 findings are one false positive, the path `src/api/qbittorrent/` in `CLAUDE.md` read as a generic API key. A search of the same history for local addresses found only placeholders (`192.168.1.10` in code comments, `umbrel.local`, `kinoseed.local`) and test values, and the README screenshots in every version show fixture data. Check again just before the repository goes public, if commits have landed since.
- [x] **Default qBittorrent login.** Settled 2026-10-23: the Umbrel package keeps `admin`/`adminadmin`. It is Umbrel's default, it is tried once, and Kinopeer asks for the login after that.
- [ ] **Dependabot alerts and security updates.** Off as of 2026-11-07, while `.github/dependabot.yml` already sends monthly version updates. The owner turns both on in the repository's Settings → Advanced Security (they work on a private repository too), so a vulnerable dependency gets a PR as soon as it's known.
- [ ] **Private vulnerability reporting.** `SECURITY.md` sends reports to Security → Report a vulnerability, which GitHub offers only on a public repository. The owner turns it on in Settings → Advanced Security right after the repository goes public; until then the link answers 404.
- [ ] **Official Umbrel App Store.** The image (`ghcr.io/kinopeer/kinopeer`) and the [Homelab Community App Store](https://github.com/MrShakhov/umbrel-homelab-store) are already public. Submit to getumbrel/umbrel-apps: manifest, icon, gallery screenshots, release notes, multi-arch image pinned by digest.
- [ ] **Links in the Umbrel manifest.** `website` and `support` in the store's `homelab-kinopeer/umbrel-app.yml` point at the public store repository and `repo` is empty while this repository is private. When the code goes public, point them and `repo` back at this repository.
- [x] **HTTPS.** Settled 2026-10-25: umbrelOS 2.0 serves Kinopeer over HTTPS with Umbrel's own certificate, and Kinopeer sets up nothing and works over plain HTTP. HTTPS set up by Kinopeer and push notifications are in [ROADMAP.md](ROADMAP.md) → Not planned.
- [ ] **Installing outside Umbrel.** Not supported yet; planned for 0.8 ([ROADMAP.md](ROADMAP.md)). When it comes: Kinopeer needs its own login (for example `KINOPEER_PASSWORD`), because without Umbrel's login anyone on the network can control qBittorrent and delete files; and onboarding must work on a clean install with qBittorrent and Prowlarr set only through the environment.
- [x] **Feature requests.** Ideas go to [GitHub Discussions → Ideas](https://github.com/kinopeer/kinopeer/discussions/categories/ideas), where people upvote them; issues are for bugs and for work we've decided to do, with a plan. Discussions are on since 2026-10-24, with an Ideas form (`.github/DISCUSSION_TEMPLATE/ideas.yml`) and links to Ideas and Q&A when opening an issue (`.github/ISSUE_TEMPLATE/config.yml`). Bugs have a form (`.github/ISSUE_TEMPLATE/bug_report.yml`) that asks for the steps and the environment [TESTING.md](TESTING.md) → When we find a bug needs, and the README links Ideas, bug reports and Q&A. Settings → About links to Ideas, a bug report (with the version filled in) and the repository; done 2026-10-28. Until the repository goes public those links open a 404 for everyone but collaborators.
- [ ] **GitHub Actions settings.** When the repository goes public, in Settings → Actions → General: turn on "Require actions to be pinned to a full-length commit SHA" (every workflow pins them since #288); require approval to run workflows for all outside contributors, not only first-time ones, since a fork's PR runs our CI with its own code; and allow only GitHub's own actions and the `docker/*` ones the workflows use. Workflow permissions stay as they are: read-only by default, and no approving of PRs (checked 2026-11-07). The deploy secrets move into a `deploy` environment that only `main` and `v*` tags can use the same day, since a private repository on GitHub Free has no environment secrets or deployment rules: its PR is prepared to merge then, with the steps in its description.
- [ ] **Required checks on `main`.** While the repository is private on GitHub's free plan, branch protection and rulesets aren't available, so CI isn't required to merge and "Allow auto-merge" stays off: PRs are merged by hand once every check passes. `gh pr merge --auto` doesn't wait in this setup: with nothing blocking the merge it merges right away, even while checks are running. When the repository goes public, protect `main` with the `check`, `docker` and `visual` checks required, then turn on auto-merge.
- [x] **Mutants for PRs from forks.** `.github/workflows/mutants.yml`'s concurrency group is keyed by the head repository and the branch (`github.event.pull_request.head.repo.full_name || github.repository`), so a run started by hand and a push's run for the same PR stay together, while two forks' PRs from a branch of the same name (`patch-1`, `main`) don't cancel each other, which the branch name alone would (#253's round 2). Its survivors go to the PR that started the run, by its number (a run started by hand looks up its branch's PR among this repository's own), so a fork's PR with the same branch name can't get them, and CI's own runs are grouped per PR too. Done 2026-11-07.
- [ ] **Features before 1.0.** Versions 0.2 to 0.4 from [ROADMAP.md](ROADMAP.md) are out; 0.5 (HTTPS and notifications) was dropped on 2026-10-25. 0.6.0 shipped on 2026-10-29 and 0.7.0 on 2026-11-05; 0.8 (beyond Umbrel) is still to come.
- [ ] **Prowlarr key from another app's data.** The Umbrel package mounts Prowlarr's config folder read-only to read its API key (the folder, not the file: a file bind mount would keep pointing at the old file after Prowlarr rewrites it). Umbrel's own Prowlarr package links apps the same way (its media-app-configurator mounts other apps' data), but the official App Store review may still question it. The fallback exists: a Prowlarr key entered in Settings → Connections is kept on the server like the TMDB key and wins over `config.xml`, so the mount can be dropped if the review asks, with the README's "Prowlarr needs no setup" changed to say where to enter the key.
